## 对 plan 的修订建议

按 AGENTS.md，改设计要先改 `docs/plan.md` 的决策记录。下面这些是验证中发现、plan 现在的写法已经不成立或不完整的地方。代码大多已经按"建议"改好，plan 还没改。

1. **Codex 哨兵改全角 `【teamflow`。**
   - 位置：6.1 对等表"输出格式"一行写的是 `[teamflow`；6.6 两段示例的首行 `[teamflow 团队看板｜…]`、`[teamflow 新动态｜…]`。
   - 改法：一律换成全角 `【teamflow …】`。
   - 依据：Codex 把首个非空白字符是 `{` 或 `[` 的 stdout 当 JSON 解析，解析失败就判这次 hook 失败、不注入（`codex-rs/hooks/src/engine/output_parser.rs` 的 `looks_like_json`）。见 S2 发现 1。
2. **S3 不通过：Claude Code 的 MCP 调用只到成员级；PostToolUse 映射可选，但必须在冻结命令串之前定。**
   - 位置：
     - 6.1"MCP 调用归属"一行（"若 M0 S3 验证 helper 能拿到会话 ID，就用请求头"）；
     - 6.5 归属表的 `X-Teamflow-Session` 一行；
     - 4.4"已知会话时带 `X-Teamflow-Session`"；
     - D04。
   - 改法：
     - Claude Code 的 MCP 调用写成"成员 + 客户端"；
     - `X-Teamflow-Session` 只出现在 `hooks/session-start`，值取 hook 输入；
     - D04 去掉"（S3 成立时的）请求头"。
   - 另起一条决策：要不要加第 5 个 hook（PostToolUse，matcher `mcp__teamflow__.*`）。
     - 这个 hook 只往 spool 写 `(session_id, tool_use_id)`；
     - 服务端按 `_meta["claudecode/toolUseId"]` 把成员级调用补成 exact；
     - 实测两者相等，v1 和 v2 运行时都成立，见 [evidence/S3_helper_env.txt](../spike/results/evidence/S3_helper_env.txt)。
     - 代价：多一条冻结的命令串，每次 MCP 调用多一次 hook 冷启动，还要依赖未文档化的 `claudecode/` 键。
     - 要做就必须赶在 D27 冻结命令串之前；不做就在 D04 写明 Claude Code 只到成员级。
3. **bare 模式不加载 hooks。**
   - 位置：
     - 6.1"无头运行"一行；
     - 6.8 无头表 `claude -p` 一行（"为 bare 成为默认做准备，脚本统一拼 `$(teamflow claude-flags)`"）；
     - 11.2 S6 的通过标准；
     - 6.8 失败降级表"Codex hooks 未信任 → 有调用、无 hook"。
   - 改法：写明 bare 下只有 MCP 和 allow 规则，`--settings` 里的 hooks 一条都不执行。下面二选一：
     - `claude-flags` 多输出 `--append-system-prompt-file <CLI 用缓存渲染的看板摘要>`；
     - 文档要求脚本开工先调 inbox。
   - "有调用、无 hook"的提醒要能区分 bare 和 Codex 未信任。
   - cc_headless.md 说 bare 将来会成为 `-p` 的默认，要跟踪这个时间点。见 S6 发现 2。
4. **isError 的文本以错误码开头。**
   - 位置：6.2 返回规范的"错误码"一条；6.3 instructions。
   - 改法：content 文本固定为 `<code>：<说明>`，例如 `needs_human：…`；structuredContent 保留 `{err, msg, …}`。
   - instructions 里按错误码下的指令（"遇到 withheld、needs_human、needs_accept……"）就能被模型看到。
   - 这属于 tools/list 和 instructions 哈希冻结之前要定的事。
   - 依据：S1 发现 3（修复前模型看不到错误码）；本轮端到端里模型拿到的原文以 `needs_human：` 开头。
5. **setup 原地替换，保持 Codex 的信任。**
   - 位置：
     - 6.1 对等表"hooks 位置"（"追加在每个事件数组的末尾"）；
     - 6.4 Codex hooks.json 的说明（"我们的组追加在每个事件数组的末尾"）；
     - 6.8 setup 第 4 步；
     - 6.8 doctor 第 3 条（"我们的组都在数组末尾"）。
   - 改法：已有 teamflow 组就原地替换（重复的去掉），没有才追加到末尾；doctor 只查"只有一组、命令串一致、Trusted"。
   - 依据：Codex 的信任键带组序号（`hooks/src/lib.rs` 的 `hook_key`），组的位置一变，我们的组和被挪动的别人的组都要重新信任。见 S2 发现 3。
6. **Codex 的会话归属用 session_id。**
   - 位置：
     - 6.1 对等表"会话 ID"一行（"根会话是 `CODEX_SESSION_ID`；子 thread 用 `CODEX_THREAD_ID`"）；
     - 6.5 归属表第一行；
     - 6.8 `doctor --live`（"从 `thread.started` 取出 thread_id，与服务端登记的会话比对"）。
   - 改法：
     - hook 输入的 `session_id` 和 tools/call 的 `_meta["x-codex-turn-metadata"].session_id` 同源（都是 `sess.session_id()`），服务端用后者匹配 hooks 登记的会话，还要过 `resolve_session`；
     - `thread_id` 只记作子线程，`turn_id` 只记录；
     - `doctor --live` 比对 `session_id`。
   - 另外 6.5 第二行"CLI 兜底 → exact"现在没有实现：兜底命令不带会话。M1 再决定要不要带。Bash 子进程里的 `CLAUDE_CODE_SESSION_ID` 是对的，但 Codex 的 shell 环境要实测。
7. **agent 写的标题要有更严的写入规则（具体化 5.1）。**
   - 位置：5.1"看见"闸门表"标题 / peer_agent"一格（"写入时更严，禁止 URL、路径、命令片段"）；8.4 测试。
   - 改法：
     - agent 来源的标题（create_task、report_blocker、update_task）在清洗之后检查；
     - 出现以下任何一种，返回 422 `invalid`，附 `rule` 和 `pos`：
       - 网址；
       - `~/`、绝对路径、`$HOME/` 这类路径；
       - `|`、`>`、`<`；
       - 反引号；
       - `$(`、`${`。
     - 人写的标题不限。
   - 8.4 的注入语料加入这 16 个样例（`server/tests/test_injection.py`）。
   - 依据：团队档下，标题是唯一不经接受就跨人送到 agent 的自由文本（评审 I6）。
8. **沙箱依赖 bwrap 和 socat；它和 CLI 兜底有冲突。**
   - 位置：6.1 对等表"凭据保护"；6.8 安装顺序、doctor 检查项；8.1 威胁表的残余风险。
   - 改法：
     - 写明 Linux 和 WSL2 上 sandbox 依赖 bubblewrap、socat，缺了 Claude Code 只警告一句就不带沙箱运行，`sandbox.credentials` 形同虚设；
     - 安装顺序加 `apt install bubblewrap socat`；
     - doctor 缺依赖时标失败（已实现）。
   - 还要定一件事：沙箱屏蔽凭据真正生效时，agent 从 Bash 跑 `teamflow inbox/note/done` 读不到凭据。6.8"MCP 握手失败 → agent 改用 Bash 调 teamflow"会失效，要么接受，要么给兜底命令另想凭据来源。见 S6 发现 5、6。
9. **UserPromptSubmit 不拉起任何进程。**
   - 位置：6.4 hook 表 UserPromptSubmit 一行（"缓存超过 60 秒时，拉起分离进程 `teamflow flush --refresh`"）；11.2 S4 的通过标准。
   - 改法：
     - 删掉拉起；
     - 改为"只读本地缓存，不联网、不拉起子进程；缓存由 Stop 每回合拉起的 `flush --refresh` 和 SessionStart 刷新"；
     - 输出用手写的最小 JSON；
     - S4 标准写明 UserPromptSubmit 要测 4 条路径：缓存新鲜、过期、有增量输出、过期且有输出。
   - 代价：每轮增量最多比上一回合结束时晚一回合。
   - 依据：评审 I3；修复前"缓存过期"路径 p95 约 69ms，修复后见上面的 S4 表。
10. **DEV 端点与反向代理。**
    - 位置：9.3 拓扑；11.3 M1。
    - 改法：
      - M0 原型的 DEV 端点（模拟手机上的人类动作）默认关，打开要有随机密钥；M1 上线前整组删除；
      - 生产 uvicorn 在 nginx 后面要加 `--proxy-headers`，`forwarded-allow-ips` 只信任 127.0.0.1。否则所有请求的来源都是 127.0.0.1，任何"只对本机开放"的判断都失效（评审 B1）。
11. **人类动作绑定版本；「转发」不授予正文。**
    - 位置：5.1 末段（`can_see_content` 的定义，以及"点「接受」或「转发给我的 agent」时，把 `through_event_id` 推进到这个值"）；7.2 一键操作。
    - 改法：
      - `can_see_content` 同时比对 `content_version` 和 `content_sha256`；
      - 表单字段：「接受」带 v、sha、seq，「认领」和「帮忙」带 v、sha；缺字段返回 400，与当前不一致返回 409，提示"内容刚被修改，请重新查看"；
      - 「转发」只推进 `through_event_id`：不能超过当前最大事件 ID，只增不减，**绝不授予或升级正文可见性**。
    - 依据：评审 I1；本轮在真实服务端上，带错的 sha 接受返回 409。
12. **会话防冒用的具体规则（6.5"防冒用"一条）。**
    - 写操作的会话必须存在、未结束，`token_id` 和 `client` 都等于当前 token，否则降为成员级并写审计。
    - hooks 条目里的 client 一律取 token 的 client。
    - 条目指向别的 token 的会话时整条忽略：`end` 也不清对方的 `current_task`。
    - 读操作不做归属。
    - 依据：评审 I2。
13. **REST 错误格式与兜底端点（4.4、6.3）。**
    - 所有 REST 错误统一为 `{"error": "<code>", "message": "…", …}`，包括 401、请求体校验失败和路由级 404/405。
    - 兜底端点：
      - `POST /tasks/{id}:note`、`:done`，返回 200 `{id, st, new}`；
      - `POST /blockers`，返回 201 `{id, st, need_state, suggest}`；
      - 对已完成的任务再调 `:done`，返回 200，只加一条进度。
    - 6.3 instructions 提到的 `teamflow note / done` 已经实现，另加了 `teamflow block`。
14. **协议的能力宣告和请求体（6.2、9.3）。**
    - 两代协议都只宣告 `{"tools": {}}`，不宣告 `listChanged`。
    - `server/discover` 和 -32022 都列出两代的全部版本。
    - `/mcp/` 先鉴权再读请求体，上限 64KB；9.3 的 nginx `/mcp/` 加 `client_max_body_size 64k`。
    - SDK 做不到的地方写在 `server/README.md`「已知协议偏差」里，升级 FastMCP 时要复核。
15. **无头示例和 `doctor --live`（6.8）。**
    - 示例统一写 `claude -p … < /dev/null`，否则可能平白多等 3 秒。
    - `doctor --live` 的提示词用提问式，不要求"逐字复述上下文"，后者会被模型安全策略拒绝（S1 发现 6）。
16. **S4 的余量与 Codex 的退回路径（6.1 不对等①、11.2 S4 的退路、D15）。**
    - UserPromptSubmit 在 Codex 的 `sh -c`、`bash -c` 下，「有输出」路径的 p95 在 28.4–32.3ms（`bash -c` 共跑 4 次，2 次超过 30）。成员的 Mac 上 Python 冷启动更慢。退路要在冻结命令串之前定，因为可执行文件路径会进 Codex 的信任哈希。可选的退路：
      - 加 `-I -S` 这类解释器参数；
      - 用更小的入口模块；
      - 接受 30–40ms。
    - Codex 走 `$SHELL -lc` 退回路径时，每个 hook 多出约 150ms（第一轮实测），UserPromptSubmit 超标；profile 有输出时 Stop 每轮都被判失败。不对等①要把耗时也写进去。
