### S11 agent 能不能替人完成断言（成员电脑）

只用测试页、测试 handle 和种子邮箱，不碰成员真实的网页邮箱和账号。要输入系统密码或 PIN 的几项，在一个临时的 macOS / Windows 测试用户下做，密码是一次性的，不要把成员自己的登录密码交给 agent。

1. Playwright（`channel=chrome`，用成员浏览器配置的一份副本）驱动测试页发起断言：人是否必须出手。
2. `claude --chrome` 在 auto 模式下打开测试页、请求验证；再让它读写种子邮箱网页版里一封模拟的回执。
3. computer use（CLI 版在 macOS，Claude Desktop 版在 macOS 和 Windows）：能不能在 macOS"使用密码"对话框、Windows Hello PIN 对话框里输入；Windows Hello 对话框接不接受 SendInput。
4. 成员实际用的密码管理器扩展，在 `userVerification='required'` 时是否不做 UV 也报 UV=true。
5. CDP virtual authenticator：在测试页上能不能产出 UV=true 的断言（预期能）。"在已登录会话里登记新凭据、立即使用，会被 H9 和数据库触发器挡住"这一半，M0 原型里还没有，等 M1 实现后由 plan 8.4 的用例覆盖。
6. iPhone 镜像、多屏协同、Phone Link 开着时：电脑上的 agent 能不能把手机导航到测试页的 T2 页；镜像状态下能不能完成用户验证。
7. 不通过（agent 不用人出手就能完成电脑上的断言）：D55 是用户拍板的，回来请用户重新拍板（推荐：T1 也收回到确认设备上做），实现者不自行收回。镜像下能完成验证的，接入要求关掉镜像，否则那台手机只做 T1。

### S12 确认设备密钥（成员手机；跨 3 天以上，和 S13 同期）

1. 在 iPhone 主屏 web app 里、Android Chrome 里，测试页各生成一把 `extractable:false` 的 ECDSA P-256 密钥，存 IndexedDB；之后每天打开签一次名、上报一次。
2. 分区可见性：Safari 标签页、主屏 web app、SFSafariViewController 三处之间能不能互相看到这把密钥，覆盖 iOS 17、18、26；加到主屏时 cookie 有没有复制过去（会话断不断）。
3. Android：从 Chrome 安装到桌面的 WebAPK 和 Chrome 是不是共享存储；厂商浏览器同样测一遍。
4. 留得住：系统更新之后、存储空间紧张之后，密钥还在不在。
5. 清掉网站数据之后能不能重新生成（M1 里重新登记要走 H9）。
6. 不通过：退到长期 HttpOnly cookie 作设备标识（`key_kind=cookie`：只算 T1 的确认设备，做 T2 一律加审批人共签）。
